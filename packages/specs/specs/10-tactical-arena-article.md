# Phase 10: Research article variant (the tactical-arena article)

Revision 2 (after the one allowed spec review). Every BLOCKER and MAJOR of that review is resolved here; the per-finding record lives with the review notes.

## Goal

Turn `/works/tactical-arena/` into a long-form, interactive research article, working title **"Stronger, Not More Human"**, without losing what phase 9 built: the card → banner morph, the banner loop, the Tier S first screen and the per-route budgets. The reader scrubs a real round, drags smokes, guesses the pros' tempo, steps a peek tick by tick, and leaves knowing exactly how far the agents are from real Counter-Strike.

1. **A "research article" variant of the works page** (P10-1), switched on by one optional frontmatter object. Banner, morph, title block, meta row and prev/next stay; the body becomes a long article with a wide figure column. Spec 09's body, gallery and Tier R rules are amended for this variant only.
2. **Figure design tokens** (P10-2): CT, T, smoke, fire, CI band and an outcome palette, contrast-checked in a unit test, each colour paired with a shape.
3. **Article data** (P10-3): per-file **whitelist projections** of the notes repo's `article/data/*.json`, validated, privacy-scanned and committed; islands fetch them as hashed static files after `client:visible`; never inlined.
4. **Shared figure libraries** (P10-4): `grid.ts`, `sight.ts` (a port of the game's sight rule that must match a parity table generated by the game's own code), scale, Elo, keyboard, motion, liveness and fact-link helpers.
5. **Twelve figures** (P10-5 … P10-15): all P0 (F1, F2, F3, F4, F6, F7, F8) and P1 (F5 stages 2–5, F9, F10, F11, F13). Hand-rolled SVG / canvas Svelte 5 islands; each has an SSR keyframe, a default state that already shows its caption's claim, a "Try this" line, keyboard control, a reduced-motion state and a JS budget.
6. **Budgets** (P10-16): first-view JS unchanged; an `article` route class and a `labFigure` class with lazy-JS limits (R2), the eager-island rule (R9) and per-island limits (new R10).
7. **Copy** (P10-17): the prose in the north-star voice; every number printed through one `<N k="…">` component that reads a keyed `facts.json`, so a bare digit in prose is a lint error; a banned-claim lint; measurement stamps.

Figure IDs (F1 … F14) and priorities are the content spec's (the notes repo's `article/STORY.md`). This spec says how they are built and accepted.

**Dataset module contract** (frozen; `src/lib/article-data/types.ts`):

```ts
export interface Dataset<P extends { schema: string }> {
  readonly name: string;                                   // output base name
  readonly schemaId: string;                               // `${name}/1`, written as `schema`
  readonly sources: Readonly<Record<string, ZodType>>;     // notes file name → source schema
  readonly projected: ZodType<P>;                          // includes schema: z.literal(schemaId)
  readonly project: (src: Readonly<Record<string, unknown>>) => P; // whitelist + rounding
  readonly maxGzip: number;
}
export function defineDataset<P extends { schema: string }>(d: Dataset<P>): Dataset<P>;
export interface Shape { readonly schema: string; readonly keys: readonly string[] }
export function shapeOf(d: Dataset<{ schema: string }>): Shape; // top-level keys of `projected`
```

- One module per output: `src/lib/article-data/<name>.ts` exports `dataset` and `type <Name>Data = z.infer<…>`. It is **owned by the figure lane that uses it**; the sync discovers modules by listing the folder, so no shared registry file is edited.
- Zod stays out of client bundles: Blocks import the module on the server and pass `shapeOf(dataset)` to the island as a prop; islands import only the type.

**Sight rule** (the game's tile sight with the settings of the line the page shows: FOV 106°, no see-behind, the directional smoke rule; the code's older defaults, FOV 90° with see-behind, are not that game):

1. **Line of sight** between tiles `a`, `b` (integer `[row, col]`): `n = 33` samples, `d = n − 1`; for `k = 0 … 32`, `num = a·(d − k) + b·k` (exact integers), sample tile = `floor((2·num + d) / (2·d))` per axis (round half up). Clear iff no sample tile is a wall. No sub-tile points, no Bresenham.
2. **Smoke ("legs" rule)**: a sample tile with smoke blocks unless that sample tile is `b`. A viewer inside smoke sees nothing; a target inside smoke can still be seen from outside; vision is directional. Smoke area: every non-wall tile within Euclidean distance 2.0 (+1e-5) of the landing tile (up to 13 tiles), walls ignored (no flood fill).
3. **Vision `canSee(i → j)`**: `d = pos[j] − pos[i]`, `dist = |d|`; facing is one of 8 directions, `u = (−cos θ, sin θ)` in (Δrow, Δcol); in cone iff `(d·u) / max(dist, 1e-6) ≥ cos(53°) − 1e-5`; seen iff in cone, `dist ≤ 10 + 1e-5`, line of sight with the smoke rule, both alive, `i ≠ j`. No see-behind. Flash blindness is out of scope for F2 (F1 reads `sees` from the replay).
4. **Orientation matters**: the 33-sample rounding is not invariant under rotation or mirroring of the map. The port works in the canonical frame of `maps_cs` (T west, CT east, A north) and so does the parity table.
5. **Symmetry**: line of sight without smoke is symmetric bit for bit; vision is not.

Constants in `SIGHT`, each with a comment: `samples: 33, fovDeg: 106, rangeTiles: 10, smokeRadius: 2.0, eps: 1e-5`; molotov radius 1.0 for F1 drawing.

**Parity table** (notes lane N). Generated by **the game's own sight functions**, run on the owner's laptop (JAX on CPU, as for the other laptop exports), with the head's settings; output `sight_parity.json` = `{ verifiedAgainstGame: true, settings, cases: [{ map, viewer: {r, c, facing}, target: {r, c}, smokes: [[r, c]], los, see }] }`, **≥ 200 cases**: 120 seeded random alive pairs on Mirage and Dust2, 40 within one tile of the range boundary, 20 within ±1° of the half-angle, 20 with smokes on the segment, on the viewer or on the target tile. Copied verbatim (test-only) to `tests/fixtures/article/sight_parity.json`. - **Chaining**: a sentence with `<N>` keys from both `elo.3v3.*` and the 5v5 keys fails unless it contains "different".
- **Literals**: "over its starting point" fails; "twice as fast", "2× faster" or "2x faster" fail unless the sentence mentions plant time or the 3v3 agent (FACTS § 4.4).
- **Stamps**: a section containing an `<N>` whose fact has `measuredOn` must contain a `<Stamp>`.
- **Honesty sentence**: "no agent has played a human or a real CS2 match" (regex `/no agent has (yet )?played (a )?human/i`) appears in section 1 within its first 120 words and again in section 8.
- **Captions**: rendered length ≤ 100 characters (with `<N>` replaced by its output), at least one `<N>`, states a claim. Every interactive figure has a `try` slot.
- **Money and hardware**: cost is "about \$40 of cloud GPU" (PRIVACY § 1, FACTS § 4.15); hardware is "a friend's RTX 2080 Ti", "a desktop GTX 1660 Ti", "my laptop".
