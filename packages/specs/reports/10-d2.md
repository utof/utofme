## Decisions and doubts

1. **`formatInterval(lo, hi, digits, { signed? })`.** The spec has three arguments; the plan's "+94 to +98" example needs signs, tempo intervals must not get them. The fourth argument is optional (default unsigned); `formatFact` passes `signed: fact.sign`. Lane FC should call `formatInterval(94, 98, 0, { signed: true })` for the Elo form.
2. **`biome.json` was edited** (not in the lane's list): `!src/data/article/**` and `!src/data/article-meta/**`. The canonical compact JSON (needed for the sidecar hash and an empty `git diff`) cannot also be Biome-formatted. Consequence: a commit that stages **only** those JSON files makes the lefthook `biome-format` job exit 1 ("No files were processed"). Issue to file: add `--no-errors-on-unmatched` to that job in `lefthook.yml` (D1's file); until then stage data with any code or docs file. Recorded in ADR 0054.
3. **Exit codes beyond the spec:** a gzip cap overrun is 1 in a sync and 3 in `--check`; unknown flags or an unknown `--only` name are 1; no `--from` and no `UTOFME_ARTICLE_DATA` is 4. With several problems the exit code is the first problem's.
4. **Sidecar `syncedAt`** is a UTC date (not a timestamp), kept while the output hash is unchanged; sidecars use the canonical serialisation (not pretty JSON) because Biome ignores the folder.
5. **Facts are scanned with the `shipped` rule set** at sync and in `--check` (stricter than the `core` scope the scanner assigns to `src/data/article-meta/**`), because fact text (`alt`, `unit`) is printed on the page. The real file passes.
6. **`check-privacy` prints key names.** `scanJson` locates a hit by JSON path, and for a denylisted JSON *key* the path is the key itself. The sync core redacts such segments; `scripts/check-privacy.ts` (lane D1) does not. Issue to file for D1's code.
7. **Facts strictness.** The shipped schema is strict per entry; the notes schema strips unknown fields (so a new field in the notes file is dropped, not shipped). An interval must have both ends and bracket `v` (all 11 real intervals do).
8. **`<N>` uses `set:text`** so Prettier's Astro printer cannot add whitespace inside the inline `<data>`; the output carries a raw U+00A0 where the spec prose writes `&nbsp;`. `measuredOnText()` ("block 28 (5v5), 2026-11-02" / "the 3v3 line, 2026-10-25") is exported from `facts.ts`; lane A2's `Stamp` takes its own `measuredOn` string, so the two wordings can be aligned by passing this text.
9. **`facts.ts` imports the committed `facts.json` statically** (validated on first use, so importing never throws). The very first sync of a fresh checkout without that file would fail to start; the file is committed, so this only matters if it is deleted.
10. **`maps_cs` ships all five maps** (the spec whitelist is `name, rows`); the held-out flag for Mirage is dropped. If F2/F10 need it, it is a spec change.
11. **Order of work:** facts schema before the CLI (the CLI's facts handling needs it); otherwise as planned. Step 4/5 tests were written first and seen failing (module missing) before each implementation.
12. **Observation for lane N:** `tempo.*.b28` facts carry `measuredOn.date` 2026-11-04 while the FACTS-sourced agent facts carry 2026-11-02; both are valid, the copy lane may want one date.
13. `bun run build` rewrites `src/data/graph.json` (existing drift, unrelated to this lane); it was restored before each commit.
