# Motion UI review (lens: motion)

## Method
- Production build (`UTOFME_FIXTURES=false bun run build`), `astro preview`, desktop Chromium 1440x900 (Playwright, headless, software rendering).
- Morph: `recordVideo` (25 fps webm) + ffmpeg frame extraction, plus a per-frame `document.getAnimations()` sampler of the view-transition pseudo-elements. Cards tested forward and Back: tactical-arena, enth, godot-ctcs, linsae (Back also on tactical-arena video).
- Jank: CDP `Emulation.setCPUThrottlingRate` 1x and 4x, rAF intervals during wheel-scroll of the home page (1800 px down and up) and hover of 6 cards, plus PerformanceObserver long tasks.
- Hover timing sampled via computed style every 60 ms; reduced motion via `reducedMotion: 'reduce'`; Pause motion via the toggle + reload.
- Fonts are fallbacks (Google Fonts unreachable): no typeface judgements.
- Limits: video is 25 fps so sub-40 ms effects are not visible in it; the 4x throttle ran on a software-rendered headless GPU, so absolute frame times are pessimistic. Not done: phone viewports, /lab/datamosh, palette open/close animation, CDP trace file.

## Top 10 to fix first
1. M-01 hero media washes out mid-morph (old fades, new late): make old stay opaque and new fade in over about 160 ms, normal blend.
2. M-02 two differently cropped copies ghost during the morph: same fix as 1.
3. M-04 add hover/tap prefetch to cards so the morph starts without the 150-220 ms dead time.
4. M-03 Back lands on a card showing a different loop frame than the banner left: carry `currentTime` over.
5. M-10 compositing load: check the caption `backdrop-filter` is not on by default and limit concurrent loops.
6. M-06 defer gallery video start until the banner swap finishes.
7. Nothing else is broken in the motion lens; M-05, M-07, M-08, M-09, M-11 and M-12 passed (not issues, listed for completeness).
8. Not covered: phone viewports and the datamosh lab (outside the time budget).
