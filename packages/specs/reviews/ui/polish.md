# UI review — polish lens

## Method
- Production build (`UTOFME_FIXTURES=false bun run build`), served with `astro preview` on :4321. The live site is unreachable from the review VM.
- Chromium via Playwright at 1440x900 @2x, 390x844 @2x (touch) and 1920x1080. Fallback fonts render (Google Fonts blocked), so there are **no typeface judgements**, only scale, hierarchy, spacing, geometry.
- Geometry was measured with `getBoundingClientRect` / `getComputedStyle`; the numbers below come from those.
- `npx impeccable@4.8.0 install` failed: the skill bundle comes from impeccable.style, which the proxy blocks (npm tarball only contains the CLI, no SKILL.md). The critique / typeset / layout / polish methodology was therefore applied by hand: rhythm, grid alignment, hierarchy, measure, contrast, consistency, anatomy. The `detect` CLI itself works (via a `--no-sandbox` Chromium wrapper) and was run on `/`, 3 project pages, `/now/`, `/garden/`, `/uses/` at 1440 and 390 (`/404-test/` returns HTTP 404 so the CLI refuses it).
- `detect` results: `line-length` (~97-103 chars) on `/works/enth|linsae|tactical-arena/` at 1440 and `straggler` (one-word last lines, advisory) on `/works/linsae/`, `/works/tactical-arena/`, `/garden/`, `/uses/` at 390. Everything else was clean. Judged below (P-12, P-13).
- Not reviewed: view-transition morph, palette, graph, datamosh interactions (other lenses).

## Phone: caption bar at 390 px
Measured: bar is 82 px high on a 186 px card = **44 %** (24 % at 1440, 18 % at 1920). Title 20 + description 17 + meta 16 + 10 px padding x2 + gaps. On touch there is no hover so the meta line is always revealed. Verdict: too much. Recommend at `(pointer:coarse)` or `<640px`: hide `.cap__m` (meta is on the project page) and clamp the description to one line, giving ~58 px = 31 %; or make phone cards 4:3 (248 px tall) so the bar is ≈ 33 %. Screenshot: `home-m-caption-leak.png`, `home_m.png`. (The file name "leak" is historical: on the desktop-sized context the meta line sits 16-26 px beyond the card bottom at rest and is clipped, which is correct; I could not reproduce visible overflow on touch.)

CSS: `@media (pointer:coarse){ .cap__m{display:none} .cap__d{-webkit-line-clamp:1} }` in `Card.astro`; `--cap-meta-h:0px` in that query so the reveal translate is also 0.

## Wide screens (1920x1080)
Left-aligned text under a full-width banner is the right call for the *text* (readable measure), but the page then reads as a banner with a left-hand stripe: 56 % of the area is empty for ~1000 px and the thumbs are tiny. What I'd do: keep the title/lede/meta/body column at `38rem`, put it at the left in a two-column grid, and put the gallery in the right column as a single stack of full-width (≈ 800 px) figures that scrolls past the text (sticky text column optional). Below 1200 px collapse to the current single column. Same idea at 1440: the text column is 712 wide beside 512 px of blank.

## Taste suggestions (5 strongest)
1. H1/lede scale-up on project pages (P-12): 36 / 22.
2. Wordmark on every page, same top offset (P-05/P-06): the single biggest consistency win.
3. Gallery as a 2-up at `--page-width` with lightbox: the screenshots are the evidence; at 348 px they aren't.
4. Fold the footer's 3-line identity block into one line (P-04) and give both toggles the same visual treatment.
5. Link colour in prose is `#0064c2` underlined but the accent `#0d99ff` appears nowhere on slash pages: use it for hover/focus underline colour and the active state so the one accent actually appears.
